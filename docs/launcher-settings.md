# Настройки и интеграция AtlasLauncher

Устанавливаемый Android HOME для ГУ OneOS. Package name: `com.geely.atlaslauncher` (Java-пакет — `com.mmwtl.atlaslauncher`).

Префикс `com.geely` выбран намеренно. OEM-плагин SystemUI (`com.ecarx.systemui.plugin`, `DynamicControlManager`) выбирает состояние климатической панели по имени пакета верхнего окна: пакетам вне белого списка, имя которых не начинается с `com.android` или `com.geely`, он всегда показывает свёрнутую панель, как полноэкранным приложениям. Для пакета `com.geely.*`, который не скрывает навигацию, панель по коду плагина должна быть полной. Это вывод из разбора APK; на ГУ его ещё нужно подтвердить. Прежние сборки с пакетом `com.mmwtl.atlaslauncher` — отдельное приложение: после установки новой сборки заново выберите HOME и добавьте виджеты, затем старое приложение можно удалить.

## Что работает в прототипе

- обычный HOME Activity без overlay и без скрытия системных панелей;
- полный список запускаемых приложений, поиск, запуск, избранное и его порядок;
- стандартные Android AppWidget: выбор, системная привязка, размещение по сетке без перекрытий, перетаскивание, изменение размера при поддержке провайдером и удаление;
- встроенные виджеты часов и дока приложений: добавление, перемещение, изменение размера и удаление;
- выбор фонового изображения и настройки дока в его виджете;
- нейтральный графитовый док с одинаковыми ячейками для избранного и кнопки «Все приложения»: ширина по содержимому, горизонтальная прокрутка при переполнении;
- отдельные окна настроек с затемнением рабочего стола, карточками параметров и мгновенным сохранением;
- вход в настройки HOME и запуск штатного Launcher3 (`com.android.launcher3/.Launcher`) из карточки «Система» общих настроек;
- кнопка Home на рабочем столе закрывает каталог и окна настроек и завершает редактирование.

Через 5 с после первого кадра HOME сообщает OEM-службе `com.autolink.diminteraction` о завершении загрузки, как она сама делает только для штатного Launcher3. Тогда QNX убирает лого Geely, а не ждёт её резервного таймера; задержка прячет под лого появление виджетов, дока и климатической панели.

Климатическая панель и верхнее меню принадлежат OEM SystemUI. Этот APK их не рисует и не управляет ими. Их поведение со сторонним HOME нужно проверить на реальном ГУ. GInputBridge для основных функций не требуется.

В `⚙` доступны 12 встроенных фонов: пролистайте ленту миниатюр и нажмите на изображение. Фон применяется и сохраняется сразу, выбранная миниатюра обведена синей рамкой. Изображения включены в APK в формате WebP, 1086×1448, суммарно около 1,6 МБ; интернет и доступ к файлам для них не нужны. Можно также выбрать своё изображение или вернуть стандартный фон.

## Сборка

Требуются Android SDK с API 35 и Java 17. В обычной среде:

```sh
ANDROID_USER_HOME="$PWD/.android-user" ./gradlew :app:assembleDebug
```

APK получает имя `<effectiveVersionName>[<versionCode>]AtlasLauncher-debug.apk` в `app/build/outputs/apk/debug/`. Базовая версия задаётся в `app/build.gradle.kts`; вне ветки `main` к ней добавляется безопасное имя ветки. APK в `artifacts/` относятся к более раннему состоянию проекта.

Релиз собирается командой:

```sh
ANDROID_USER_HOME="$PWD/.android-user" ./gradlew :app:assembleRelease
```

При текущем `targetSdk=30` стандартную release-сборку блокирует проверка Google Play `ExpiredTargetSdkVersion`. Для локального APK головного устройства после отдельной проверки отчёта Lint можно явно пропустить её:

```sh
ANDROID_USER_HOME="$PWD/.android-user" ./gradlew :app:assembleRelease -x :app:lintVitalRelease
```

`lintDebug` продолжает сообщать об этой ошибке; SDK и правила Lint не изменены.

Подпись подключается через локальный игнорируемый `secure.signing.gradle`, как в AtlasMediaWidget. Скопируйте `app/secure.signing.gradle.example` в корень под этим именем и укажите существующий ключ AtlasMediaWidget, alias и пароли. Можно задать другой скрипт через `-Psecure.signing=/path/to/secure.signing.gradle`; относительный путь к ключу считается от корня AtlasLauncher. Ключи и пароли в Git не добавляются. Подписанный APK: `app/build/outputs/apk/release/<effectiveVersionName>[<versionCode>]AtlasLauncher-release.apk`. Без локального скрипта Gradle создаёт APK с суффиксом `-unsigned`; он не готов к установке. Обновление установленного приложения требует совпадения подписи; release APK не заменит debug APK с другим ключом.

Иконка приложения — адаптивный векторный знак с шестью ячейками и доком на графитовом фоне (знак `#7893A0`, фон `#171717`, как в AtlasMediaWidget); для Android 13+ предусмотрен монохромный вариант.

Интерфейс рассчитан только на портретный экран ГУ. Режим редактирования открывается долгим нажатием на свободное место, виджет или док. Часы можно добавить в этом режиме через `＋` → `Часы`. Док приложений добавляется там же как встроенный виджет. Окно `＋` показывает виджеты карточками с миниатюрой, приложением и минимальным размером в ячейках. Миниатюра берётся из `previewImage` виджета, а если его нет — используется значок; превью загружаются в фоне. Для часов и дока показывается собственный предпросмотр. [Снимок окна виджетов](../qa/widget-previews/report.md). При обновлении прежний видимый док переносится в сетку автоматически; если он был скрыт, его можно добавить вручную. Док можно передвинуть над нижней системной панелью, изменить его размер или удалить и позже добавить снова. При удалении список закреплённых приложений сохраняется. Сохранённые виджеты показываются при обычном запуске. Область размещения заканчивается в 150 физических пикселях от нижнего края Activity, над климатической панелью; целые строки сетки прижаты к этой границе, а остаток высоты уходит наверх. Короткое нажатие на свободное место завершает редактирование. Кнопка «Назад» его не завершает: OneOS превращает свайп от края экрана на любом HOME, кроме Launcher3, в «Назад», и перетаскивание у края иначе выходило бы из режима. При перемещении и изменении размера под виджетом показывается синяя рамка места и размера, которые он займёт после отпускания; красная рамка на исходном месте означает, что места нет и виджет вернётся назад. Кнопки добавления, завершения и общая шестерёнка настроек видны только в этом режиме. Долгое нажатие на док, как и на любой другой виджет, включает режим редактирования; настройки дока открываются шестерёнкой самого виджета в этом режиме. В одном окне доступны состав и порядок приложений, показ кнопки «Все приложения», размер значков и подписи дока (действие кнопки выбирается в общих настройках `⚙`); закрепление приложений выполняется там же. Отключённое или удалённое приложение не пропадает из списка закреплённых автоматически: док его не показывает, а в настройках дока оно помечено «недоступно» и убирается кнопкой ×. После повторного включения или установки значок возвращается в док. При первом показе старые координаты привязываются к ближайшим свободным ячейкам сетки; размеры также округляются до ячеек. Живой карты и навигации в этой версии нет. Activity фиксирует портретную ориентацию. Точную позицию над OEM-панелью нужно проверить на реальном ГУ. [Снимки прежнего оформления](../qa/scenic-preview/home.png) и [отчёт прежней функциональной проверки на эмуляторе](../qa/freeform-widgets/report.md).

Штатные виджеты OneOS (медиа, телефон, галерея) нарисованы под Launcher3 карточками фиксированного размера. Atlas не обрезает их, а равномерно масштабирует в ячейку с обычными отступами, чтобы края совпадали с соседними виджетами; свободная высота остаётся снизу.

Штатный медиавиджет OneOS (`com.geely.mediawidget`) по нажатию на значок источника просит Launcher3 показать список источников, поэтому на другом HOME это нажатие ничего не делает. Atlas замечает нажатие на этот значок сам и показывает над виджетом тот же список — виджет `SourceListWidgetProvider` во всплывающем окне, как в Launcher3. Для списка Atlas привязывает отдельный скрытый ID виджета; при первом нажатии Android может запросить разрешение на привязку, после него список открывается следующим нажатием. Список закрывается касанием вне его, нажатием внутри (выбор источника), кнопкой HOME и в режиме редактирования. [Проверка](../qa/media-source-list/report.md).

Общая шестерёнка в режиме редактирования открывает одну страницу настроек без вкладок: карточки «Фон рабочего стола», «Отступ виджетов по бокам» и «Система». Отступ сужает сетку виджетов слева и справа на ½ или 1 ячейку (48 или 96 dp); на экране шириной 1440 dp это 14 или 13 столбцов вместо 15. Координаты виджетов отсчитываются от края сетки, поэтому после смены отступа виджеты сдвигаются вместе с ней, а не помещающиеся переносятся в свободные ячейки. [Проверка](../qa/widget-side-margin/report.md). Док, часы и другие виджеты настраиваются только шестерёнкой на самом виджете в режиме редактирования; в общих настройках их параметров нет. Окна закрываются кнопками «Готово», × или системной кнопкой «Назад»; нажатие на затемнённый фон их не закрывает. Содержимое прокручивается, заголовок и кнопка «Готово» остаются на месте. Открытое окно восстанавливается при пересоздании Activity. [Снимки и проверка новых окон](../qa/focused-settings/report.md).

В режиме редактирования у часов есть отдельная кнопка настроек. Она открывает окно с живым предпросмотром и всеми параметрами: формат времени (`как в системе`, `24 часа`, `12 часов`), отображение даты, начертание (`тонкий`, `обычный`, `жирный`) и семейство шрифта (`без засечек`, `с засечками`, `моноширинный`). Эти параметры сохраняются отдельно от положения и размера виджета. Блок встроенных часов занимает ширину времени и даты, округлённую до ячеек сетки. При обновлении существующий блок сужается с сохранением размера цифр; новый размер сохраняется после перезапуска.

Каталог «Все приложения» использует тот же графитовый стиль, что и док. Окно каталога занимает до 1200×1400 dp, его значки имеют фиксированный размер 96 dp, а подписи приложений всегда видны. Сетка подстраивается под ширину экрана. Размер значков дока (40–160 dp, в настройках — ползунок без числового значения) и показ подписей в доке настраиваются в виджете дока. Значки дока равномерно распределяются по его ширине. Док всегда использует плотные отступы; без подписей и со стандартными отступами виджета Android 11 (4 dp сверху, 20 dp снизу) док с иконками до 56 dp можно уменьшить до одной ячейки 96 dp; более крупное содержимое требует больше ячеек. Параметры сохраняются после перезапуска.

В общих настройках `⚙`, в карточке «Все приложения», можно изменить действие кнопки «Все приложения» дока (и такой же кнопки панели климата, если включён её перехват): встроенный каталог, GLauncher (GIB), экспортированная Activity установленного приложения или компонент, введённый вручную как `package.name/.ActivityName`. Готовый вариант GLauncher использует `com.salat.gbinder/com.salat.gbinder.AppLauncher` — экспортированный alias из проверенного локального APK GIB 4.6.1 (1719). GIB должен быть установлен и настроен на устройстве. Переход из кнопки дока в окно GLauncher проверен на эмуляторе; на реальном ГУ пока не проверен. Если выбранная Activity недоступна или запрещена для внешнего запуска, лаунчер сообщает об этом и открывает встроенный каталог. Для выбранной Activity настройки показывают название приложения и Activity, а не имя компонента.

После установки выберите AtlasLauncher в системном выборе домашнего приложения. В окне `⚙` (долгое нажатие на рабочий стол), в карточке «Система», есть переход в настройки HOME для возврата к штатному Launcher3. Штатный APK удалять не требуется.

### Скрытие панели климата

`⚙` → «Панель климата» → «Скрывать панель на главном экране» скрывает OEM-панель климата, пока на экране AtlasLauncher; по умолчанию она показывается. Для этого Activity выставляет `SYSTEM_UI_FLAG_HIDE_NAVIGATION` с `SYSTEM_UI_FLAG_IMMERSIVE_STICKY`: плагин SystemUI скрывает панель у пакетов `com.geely.*` с этим флагом. В других приложениях панель ведёт себя как обычно. Область виджетов при этом заканчивается в 24 физических пикселях от нижнего края вместо 150; если в освободившуюся высоту помещается новая строка сетки, она добавляется снизу. Когда панель возвращается и строка пропадает, виджеты из неё переносятся в ближайшие свободные ячейки, и новое расположение сохраняется. Работа на ГУ ещё не проверена.

### Кнопки «Домой» и «Все приложения» на панели климата

Кнопки «Домой» и «Все приложения» на OEM-панели климата явно открывают `com.android.launcher3/com.android.launcher3.Launcher` (`JumpUtils.jumpToHome` в плагине SystemUI), а не текущий HOME, поэтому выбор AtlasLauncher как HOME на них не влияет. Кнопки отличаются только extra `screenId` в интенте (0 — «Домой», 2 — «Все приложения»). Для обхода есть необязательная служба специальных возможностей `StockHomeRedirectService`: когда на экране появляется окно `com.android.launcher3.Launcher`, она открывает AtlasLauncher. Если перед этим (не раньше чем за 2 секунды) была нажата кнопка «Все приложения» панели, AtlasLauncher сразу выполняет действие кнопки «Все приложения» своего дока: встроенный каталог или Activity, выбранную в общих настройках в карточке «Все приложения». Кнопку панели служба узнаёт по положению: плагин закрепляет её первой в списке `rv_nav_sub` и не даёт перетаскивать (ни подписи, ни описания у кнопок нет). Launcher3 при этом на мгновение мелькает.

Включение: `⚙` → «Панель климата» → ««Домой»: возвращать на AtlasLauncher» и/или ««Все приложения»: как кнопка в доке» (переключатели независимы), затем в «Специальных возможностях Android» включите службу «AtlasLauncher: кнопки панели климата» и подтвердите системный диалог. Строка под переключателем показывает, подключена ли служба. Если раздел специальных возможностей на ГУ скрыт, службу можно добавить через ADB, сохранив уже включённые службы (например, GInputBridge):

```sh
CUR=$(adb -s SERIAL shell settings get secure enabled_accessibility_services | tr -d '\r')
adb -s SERIAL shell settings put secure enabled_accessibility_services "com.geely.atlaslauncher/com.mmwtl.atlaslauncher.StockHomeRedirectService:$CUR"
```

Если `CUR` равно `null`, укажите только компонент AtlasLauncher.

Особенности:

- Служба получает только события смены окон Launcher3, а при включённой функции «Все приложения» — ещё и нажатия в пакетах панели (`com.ecarx.systemui.plugin`, `com.android.systemui`). Право читать содержимое окон (`canRetrieveWindowContent`) нужно только для проверки, что нажатый элемент — первый в `rv_nav_sub`; после обновления APK Android может попросить подтвердить службу заново. Когда оба переключателя в AtlasLauncher выключены, служба не запрашивает ни одного типа событий, и система ей ничего не передаёт; привязка к уже запущенному процессу HOME остаётся. Чтобы убрать службу совсем, выключите её в специальных возможностях Android.
- Перехват срабатывает, только пока HOME — AtlasLauncher. После возврата HOME на Launcher3 кнопки панели снова открывают штатный лаунчер.
- «Открыть штатный Launcher3» в настройках AtlasLauncher не перехватывается в течение 5 секунд.
- Если включена только функция «Домой», «Все приложения» на панели тоже возвращают на рабочий стол AtlasLauncher. Если включена только функция «Все приложения», «Домой» открывает Launcher3.
- Распознавание кнопки «Все приложения» выведено из декомпиляции плагина (`SubAreaViewModel`, `dockPresetData.json`) и проверено только на эмуляторе без панели; на ГУ его нужно подтвердить.
- Принудительная остановка AtlasLauncher (`am force-stop`, «Остановить» в настройках приложения) в Android 11 отключает службу: система убирает её из включённых и не подключает снова до перезагрузки или обновления APK. После обычного сбоя процесса служба подключается сама.

Подробный план и ограничения: [docs/launcher-prototype-plan.md](../docs/launcher-prototype-plan.md). Исходные OEM APK для анализа: [reference-apks/README.md](../reference-apks/README.md).

Пошаговая проверка на ГУ и команды возврата к штатному HOME: [docs/head-unit-test-and-rollback.md](../docs/head-unit-test-and-rollback.md). Протокол выполнен на ГУ ATLAS ОД.
