# Штатный медиавиджет и медиацентр OneOS

Часть 1 — список источников штатного медиавиджета на стороннем HOME (2026-09-29). Часть 2 — что отдаёт медиацентр напрямую.

## Проблема

`com.geely.mediawidget` (`SourceWidgetProvider`, `SourceBigWidgetProvider`) по нажатию на `rl_swicth_area` / `iv_mediaWidget_switch` / `iv_marker` вызывает `content://com.android.launcher3.interactive`, метод `media_source_show`. Launcher3 показывает над виджетом `PopupWindow` с AppWidget `SourceListWidgetProvider`. Если окна Launcher3 нет (HOME — Atlas), вызов игнорируется. Authority провайдера занят Launcher3, объявить такой же в Atlas нельзя.

## Решение

Контейнер виджета из пакета `com.geely.mediawidget` отслеживает касания (не перехватывая их). Если касание-тап попало в один из трёх элементов переключателя (ID берутся из ресурсов пакета, для этого пакет добавлен в `<queries>`), Atlas показывает над виджетом `PopupWindow` с `SourceListWidgetProvider`. ID этого виджета хранится в `SharedPreferences("home")` под ключом `source_list_widget` и не удаляется очисткой «лишних» ID при запуске. Окно выровнено по низу, поэтому при подгрузке строк растёт вверх. Закрывается касанием снаружи, через 300 мс после тапа внутри (выбор источника: сам виджет сообщает об этом только Launcher3), в `onStop` и при перестроении сетки.

## Размер и скругление карточки

Launcher3 держит виджеты без отступов хоста (`LauncherAppWidgetHostView.setPadding(0, 0, 0, 0)`), а корень разметки штатных виджетов OneOS имеет фиксированный размер в пикселях, больше объявленного минимума: `SourceWidgetProvider` 516×224 при `minWidth/minHeight` 392×184, `SourceBigWidgetProvider` 480×480 при 392×392. Скругление нарисовано в фоне карточки (`card_bg.png`, `big_widge_bg.webp`), Launcher3 углы не обрезает (`mEnforcedCornerRadius` всегда 0). Хост центрирует такой корень, поэтому в Atlas со стандартными отступами (на ГУ и эмуляторе 12/4/12/20 dp) карточка обрезалась по краям вместе со скруглениями, а список казался шире карточки.

Теперь для любого виджета, у которого корень `initialLayout` имеет фиксированный размер (в том числе телефон и галерея OneOS), `FittedWidgetView` равномерно масштабирует карточку в область ячейки за вычетом обычных отступов: верх и боковые края совпадают с соседними виджетами, свободная высота остаётся снизу. Ячейки для нового виджета считаются по размеру карточки без отступов (большой медиа 5×5, масштаб 0,95; малый 6×3, масштаб 1,07); уменьшать можно до объявленного минимума. Чтобы прочитать разметку чужого пакета, в `<queries>` добавлены пакеты с действием `APPWIDGET_UPDATE`. Список источников масштабируется до ширины карточки и стоит вплотную над ней.

Эмулятор `atlashu` (Android 11, API 30, 1440×1920, 160 dpi), debug APK `0.5.0[15]`, на эмулятор установлен `reference-apks/oneOS_MediaCenterUI.apk`.

## Ограничения

- На эмуляторе нет медиасервиса Geely: у виджета нет обработчиков нажатий, а список пуст (видна только белая полоса отступов). Поэтому код временно проверялся с срабатыванием на `ACTION_DOWN`; финальный вариант проверен тапами, так как касания доходят до контейнера через долгое нажатие `AppWidgetHostView`. Реальный вид списка, выбор источника и его закрытие нужно проверить на ГУ.
- Высота окна берётся из содержимого, а не из `height`, который виджет передаёт Launcher3.
- Если над карточкой мало места, список прижимается к верхнему краю экрана и перекрывает карточку, как `showAsDropDown` в Launcher3. Размещайте медиавиджет ниже.
- Телефон и галерея OneOS не проверены: их нет на эмуляторе. Вписывание сработает, если корень их `initialLayout` имеет фиксированный размер.
- Фон с нарисованными углами при масштабе ≠ 1 интерполируется; на ГУ при 160 dpi возможна лёгкая мягкость краёв.
- Диалог разрешения на привязку не проверялся; после разрешения список открывается следующим нажатием.
- Launcher3 по-прежнему получает `media_source_show`; без его окна он запрос отбрасывает (`window token == null`), но если Launcher3 жив в фоне, он может показать окно у себя — невидимо, пока открыт Atlas.

## Медиацентр `com.geely.mediacenterservice`

Замысел (2026-09-29, пока не реализован) — встроенный в Atlas медиавиджет, неотличимый от штатного (малый 516×224 и большой 480×480), без ошибки штатного: после загрузки он иногда остаётся «источник недоступен», пока не откроется полноэкранное приложение. Решено перечитывать состояние при привязке, возврате на HOME и смерти Binder. Источники: радио, BT, USB, CarPlay при подключении; «онлайн» эта прошивка скрывает.

Доступ: привязка к `MainService` (действие `android.intent.action.GEELY_MEDIACENTER_SERVICE`) → `IMediaCenter`, сырые Binder-транзакции с кодами из декомпилированного `oneosapi`. Проверки вызывающего в службе нет. Порядковые номера `AudioSource`: USB 1, BT 2, RADIO 3, ONLINE 4, YUNTING 6, CPAA 7.

Первый шаг — диагностика `MediaCenterProbe` («Система» → «Диагностика медиацентра OneOS», тег logcat `AtlasMediaProbe`). Подтверждено на ГУ 2026-09-29 (release `0.5.0[15]`):

- текущий и активный источник (радио = 3);
- для BT — название, исполнитель, альбом, длительность и позиция трека; обложка приходит URI `content://com.android.bluetooth.avrcpcontroller.AvrcpCoverArtProvider`, не картинкой;
- радио: диапазон 1, частота `100100` (= 100,1 МГц), статус `4097` — играет;
- состояние воспроизведения: 0 — PLAY, 1 — PAUSE, 2 — STOP.

Штатный виджет сам не показывает ни обложку, ни название станции, так что для клона они не нужны. Эмулятор медиацентр не запускает: служба работает с системным UID.
