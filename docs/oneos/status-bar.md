# Плашка «Сейчас играет» в строке состояния

Разбор двух сборок `SystemUIPlugin` из `reference-apks/`, 2026-10-07. Вопрос: почему на машине с прошивкой `1.0.20260326G(87)` в строке состояния есть плашка с текущим треком, а на G636 нет.

## Причина

Плашка — `LeftTempStateContainer` / `LeftTempStateViewModel` (ключ `music`) в `com.ecarx.systemui.plugin`. Данные она берёт только из MediaCenter OneOS (BT, USB, радио, онлайн/wecarflow, Yunting; в сборке G87 добавлен CPAA), а не из любых Android MediaSession. Пока приложение-источник на экране, плашка скрыта.

- **G636 `1.0.20250623G(312)`:** `init()` подключает слушатели сцены, навигации, багажника и звонков, но никогда не вызывает `initMusicPlaying()` (приватный метод, вызовов нет). Слушатели MediaCenter не регистрируются, и плашка не появится никогда. Настройки, свойства или флага, который бы это включал, нет — это мёртвый код.
- **G87 (flavor `g426`, другая модель):** `init()` вызывает `initMusicPlaying()`.

Включить плашку на G636 без нового OEM-плагина (OTA) нельзя: плагин подписан платформенным ключом, `/system` защищён verity ([подписи](firmware-signatures.md)).

## Обходной путь

Atlas может зарегистрировать собственный сервис через `addService` OneOS API ([OneOS API](oneos-api.md)). Проба в ветке `statusbar-scene-probe` (`StatusBarProbe.java`), подтверждена пользователем на ГУ 2026-10-07:

- **сцена** (тип 13) — плашка показывает значок сцены и произвольный текст. Это чистый вариант. Если заголовок сцены уже показан, плагин держит старый — для обновления нужно закрыть и открыть сцену заново;
- **навигация** (тип 1) — текст плашки плагин собирает сам: расстояние + единица + «后进入» + `nextRoadName`. Китайскую вставку не убрать: есть только строки zh по умолчанию, `TextView` однострочный с бегущей строкой.

## Цвет значков

Строка состояния на главном экране — 96 px из 1440×1920 (`ITYPE_STATUS_BAR` в `dumpsys window` на ГУ, `status_bar_height` в плагине). Цвет значков плагин выбирает по `systemUiVisibility` окна в фокусе (`StatusBarView.onWindowChange`, выведено из кода G636 и G87):

- `SYSTEM_UI_FLAG_LIGHT_STATUS_BAR` (`0x2000`) — чёрные значки;
- `0x4000` — белые (в Launcher3 это `SYSTEM_UI_FLAG_DARK_STATUS_BAR`), заодно панель дока становится плотнее: `#99000000` вместо `#66000000`;
- ни одного флага — ресурсы по системному режиму: днём `#2d3035`, ночью `#fafcff`.

Поэтому для белых значков днём нужен `0x4000`: просто снять `0x2000` недостаточно.

Плагин отбрасывает `windowChange`, пока его строка состояния не создана, но потеря не страшна: `DisplayPolicy.updateSystemUiVisibilityLw` шлёт `windowChange` до проверки изменений, в том числе после проходов раскладки окон (`finishPostLayoutPolicyLw`). В логе загрузки от 2 октября после создания строки таких вызовов для окна Atlas было ещё 21. Окно строки SystemUI подключает раньше плагина: плагин создаётся в отложенной транзакции `CollapsedStatusBarFragment` (выведено из кода). Atlas может быть разложен и раньше окна строки, тогда её высота приходит позже как изменение отступов окна.

Проверять флаг нужно по `mLastSystemUiFlags` в `adb shell dumpsys window`: `vsysui` показывает только известные AOSP флаги, и `0x4000` в нём не виден.
