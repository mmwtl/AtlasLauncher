# Возврат на Atlas с кнопки «Домой» панели климата

Дата: 2026-09-29. Устройство: эмулятор `atlashu`, `sdk_gphone_arm64`, Android 11 / API 30, 1440×1920, 160 dpi. На эмуляторе установлен OEM `com.android.launcher3` 1.0.20250623G(312) и GInputBridge со своей службой специальных возможностей. Версия приложения: 0.5.0 (15), debug, пакет `com.geely.atlaslauncher`.

OEM SystemUI и плагин панели на эмулятор поставить нельзя: они подписаны платформенным ключом (`sharedUserId="android.uid.systemui"`), а вызов `windowChange` есть только в OEM-фреймворке. Нажатие кнопки панели воспроизводилось тем же явным интентом, что в `JumpUtils.jumpToHome`: `am start -n com.android.launcher3/com.android.launcher3.Launcher` (с `--ei screenId 2` для «Все приложения»).

## Проверки

| Сценарий | Результат |
| --- | --- |
| Переключатель выключен, служба разрешена | `dumpsys accessibility`: `eventTypes=` (пусто); Launcher3 остаётся на экране |
| Включение переключателя | `eventTypes=TYPE_WINDOW_STATE_CHANGED`, статус «Служба работает.» |
| Разрешение через «Специальные возможности» | Служба видна в списке, системный диалог подтверждения, GInputBridge остаётся включённым |
| Явный запуск Launcher3 (кнопка «Домой» панели) | Возврат на `com.geely.atlaslauncher/com.mmwtl.atlaslauncher.HomeActivity` |
| То же с `screenId=2` («Все приложения») | Возврат на рабочий стол Atlas |
| «Открыть штатный Launcher3» в настройках Atlas | Launcher3 остаётся открытым |
| HOME возвращён на Launcher3 | Перехвата нет, Launcher3 остаётся |
| Обновление APK (`install -r`) | Служба остаётся включённой и подключается |
| `am crash` процесса Atlas | Процесс перезапущен, служба подключилась сама, перехват работает |
| `am force-stop` Atlas | Android убрал службу из включённых; повторное включение в настройках не подключило её («Crashed services») до обновления APK. Статус в Atlas показывает «Служба не работает…» |
| Выключение переключателя при подключённой службе | `eventTypes=` сразу, перехвата нет |

Состояние компонента (`setComponentEnabledSetting`) для выключения не подходит: на API 30 `AccessibilityManagerService` не перечитывает службы при изменении отдельного компонента, и включённая так служба не появлялась в списке специальных возможностей.

## Ограничения

- На ГУ не проверено: мелькание Launcher3, доступность раздела специальных возможностей в OneOS, поведение `screenId`.
- Полная климатическая панель для пакета `com.geely.*` — вывод из разбора плагина; на эмуляторе не проверяется.
